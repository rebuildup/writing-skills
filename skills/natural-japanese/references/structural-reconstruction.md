# 構造的な推敲 — 解体と再構築

AIが書いた日本語の不自然さは、単語よりも文の骨格に原因があることが多い。禁止語を言い換えても骨格はそのまま残り、別の言い換えで同じ癖が戻る。この reference は、文の意味要素をいったん分解して組み直す推敲を扱う。

[nanaism/yomiyasu](https://github.com/nanaism/yomiyasu)（MIT）の考え方を、このSkillの工程に合わせて短くまとめたものである。意味を変えていないかの確認は `semantic-fidelity.md` が担当し、この reference は「何を直すか」を担当する。

## 3つの構造的な病理

### 1. 非生物主語と比喩動詞

概念や道具が主語になり、身体的な比喩の動詞が付く。

- 「設計が静かに壊れる」「エラーが黙って無視される」「前提が崩れる」
- 「見積もりの甘さが判断を遅らせた」

誰が何をしたのか、何が原因で何が起きたのかが文から消える。

### 2. 名詞の連続と構文の消失

述語を動詞に開かず、サ変名詞を「の」でつなぎ、体言止めで終える。

- 「メッセージ処理遅延の発生。」「設定値の適切な管理の徹底」

専門用語は並ぶが、主語・目的語・動詞・条件が消え、手順や因果として読めない。

### 3. 過剰な装飾と不要な否定対比

太字、分断された箇条書き、「AではなくBだ」という演出の否定、全角コロンや装飾の絵文字が重なる。強調が増えるほど、どこが重要かは分からなくなる。

## 解体と再構築の4段階

病理を見つけたら、言い換えではなく次の順で組み直す。

1. **行為者を特定する** — 実際に判断し、作業し、起こしているのは誰か（何か）。
2. **事実に戻す** — 比喩でぼかされた出来事を、何が起きたか・何をしたかとして書く。
3. **主述関係を戻す** — 行為者を主語にし、目的語と述語の動詞を補って、文を一つの出来事として成立させる。名詞の連続は動詞に開く。
4. **装飾を地の文に戻す** — 不要な太字、文を分断する箇条書き、意味を担わない否定対比を、つながった文にする。

例：

- 前：「メッセージ処理遅延の発生。リトライが黙って無視される。」
- 後：「キューにメッセージが滞留し、処理が遅れた。リトライが無効になっていたため、失敗してもエラーログが残らず、原因の特定に時間がかかった。」

後の文は、前の文と前後の文脈から分かる事実だけで組み直している。原因や主体が文脈から分からなければ、推測で補わない。

## 直しすぎを防ぐ条件

構造を直す時も、意味と書き手の意図は変えない。

- **分からないものは足さない。** 行為者・原因・条件・数値が原文や提供された文脈から分からない場合、それらしい内容を創作しない。ぼかした語を、より狭い具体的な事実へ勝手に置き換えない。組み直せないなら原文の語を残し、書き手に確かめたい点として挙げる。
- **含みを残す。** 比喩や副詞が担っていた評価や気持ちの向き（「うっかり」の不注意、「ようやく」の待ちくたびれた感じ、「〜てしまった」の後悔）は、ふだんの言葉で残す。確度や程度を強める語は足さない。
- **道具の働きを述べる文は直さない。** 「このツールはログを集める」のように仕組みを客観的に述べる非生物主語は自然な日本語である。直すのは、道具や概念に意志や感情を持たせる擬人化と、人の行動を抽象名詞の作用として書いた文である。
- **定着した慣用句は残す。** 「骨が折れる」「手を焼く」のように、AIが広まる前の人の文章でもふつうに見かける言い方はAIらしさとして扱わない。
- **文書の種類に合わせる。** 報告書の「障害が発生した」のように文書の種類に合う語は残す。エッセイや小説で、何を何に例えたか読み取れる比喩は書き手の個性として残す。
- **意味を担う否定は残す。** 誤解されがちなAを打ち消してBと言い直している否定は、肯定文に変えない。

## 指示文も同じ基準で書く

推敲の指示やSkill自体を比喩動詞や名詞の連続で書くと、モデルはその文体を模倣する。この reference と、それを呼ぶ指示文も、行為者と動詞が見える文で書く。

## 検出

`lint.py` は、比喩動詞と一部の非生物主語の典型を `metaphor_verb` として検出する。finding は見直し候補であり、上の条件に照らして「組み直す / 残す」を判断台帳で決める。
